# 我要参与

《今文佛典》不是一次性的展示页面，而是一个长期整理、持续校订的佛经现代语译项目。我们希望建立一套可以逐步扩展、反复修订、公开协作的佛典文库，让更多人既能读懂经典，也能参与到文本整理本身。这个项目的基本分工是：现代语译初稿主要由现代强大的大模型 AI 生成，人工负责校验、修订、取舍与最终把关。

## 项目初衷

- 让佛经进入今天的语言环境，降低第一次阅读的门槛
- 保留关键佛学概念，不把经典简化成口号式浅白文字
- 用 Markdown 管理文稿，让每次修改、校对和讨论都可以被记录
- 用大模型 AI 先形成高效率初稿，再由人工持续校验和修订
- 逐步形成一套适合长期协作的佛经现代语译工作流

## 我们为什么要这样做

传统佛经文本往往语言凝练、断句复杂、术语密集。对很多读者来说，问题不在于有没有兴趣，而在于很难找到一份既尊重原典又真正可读的现代语版本。这个项目想做的，不是简单“白话化”，而是在尽量忠于原义的前提下，先借助大模型 AI 形成可工作的现代语初稿，再由人工持续校验，做出可读、可改、可校对的文稿。

## AI 与人工分工

- 现代语译初稿：主要由现代强大的大模型 AI 生成
- 人工职责：核对原义、检查术语、修正文气、补充必要说明、控制误译与过译
- 项目重点：不是组织人工从零逐句翻译，而是建立一套 AI 初稿加人工校验的高质量工作流

## 你可以怎么参与

在这个项目里，文稿协作默认发生在 GitHub 上。参与者至少需要会这些基本操作：

- 能登录 GitHub，阅读仓库里的 Markdown 文稿
- 能在 GitHub 上直接编辑文件，或基于分支 / Pull Request 提交修改
- 能在评论区说明修改理由，并根据反馈继续修订

如果你还不熟 GitHub，也可以先从阅读、校对建议或术语反馈开始；但如果要正式参与写作和修订，建议先具备基本 GitHub 协作能力。

### 1. 新增内容

- 认领一部短经，先完成结构草稿
- 基于 AI 初稿补入原文、现代语译、关键词和简注
- 新增新的卷稿、章节稿或术语附录

### 2. 人工校验

- 校对原文录入是否准确
- 检查 AI 生成的现代语译是否偏离原义
- 统一术语译法，例如“空”“得”“相”“般若”等高频概念
- 标出句子不通顺、断句可疑或释义过满的地方

### 3. 结构整理

- 优化卷、品、章的拆分方式
- 调整 front matter 字段和状态规则
- 补充目录、索引、修订记录等支持性内容

### 4. 阅读反馈

- 从普通读者角度指出哪里仍然难懂
- 标出哪些段落需要更多背景说明
- 反馈哪些译法清楚、哪些译法容易误解

## 当前最需要的帮助

- 为常见短经整理和校验 AI 生成的第一轮现代语初稿
- 为已完成文稿做人工复校
- 整理术语表，减少同一概念的漂移译法
- 为长经建立按卷、按品推进的协作方式

## 协作建议

如果你要参与，建议先从一篇短经或一个卷稿开始，不要一开始就覆盖整部大经。比较适合起步的工作有：

- 校对《心经》或《八大人觉经》的已成稿内容
- 为《金刚经》整理和修订前几分的 AI 现代语译初稿
- 为《药师经》或《无量寿经卷上》补术语说明
- 帮忙把一篇文稿从“翻译中”推进到“人工已校验”

## 文稿工作方式

所有原始稿都使用 Markdown 管理，并放在 `content/sutras/` 下。每篇文稿都带有 front matter，用于记录：

- 标题
- 卷别
- 翻译状态
- 校验状态
- 完成进度
- 最后更新时间

这意味着每次新增、修改、校对都可以像普通代码一样提交、审阅和回退。实际协作入口会放在 GitHub 仓库中，因此参与写作者需要能在 GitHub 上完成浏览、编辑、提交和讨论。这里的核心工作，主要是围绕 AI 译稿做人工校验和修订，而不是从零开始手工翻译整部经典。

## GitHub 协作要求

- 参与写作前，先阅读仓库里的现有文稿与目录结构
- 修改正文、front matter 或状态字段时，尽量一次只做一类改动
- 提交时写清楚这次修改做了什么，例如“补全《心经》关键词”或“修正《金刚经》第一节断句”
- 如果是大改，优先通过 Pull Request 讨论，不要直接覆盖别人正在推进的稿子
- 对术语、句读、释义有争议时，把理由写在 GitHub 的评论里，便于后续追溯

## 参与前建议先看

- 项目首页：了解整体目标和展示方式
- 经文目录：看当前有哪些稿件、状态如何
- 示例文稿：先感受一篇完整稿的体例
